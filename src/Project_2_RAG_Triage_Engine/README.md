# Context-Aware Security Operations Triage: Mitigating SOC Alert Fatigue via RAG-Driven Pipelines

## 📌 1. Academic Problem Statement: The Crisis of "Alert Fatigue"
Modern Security Operations Centers (SOCs) face an overwhelming influx of telemetry logs generated by Security Information and Event Managers (SIEMs), Extended Detection and Response (EDR) platforms, and edge firewalls. In a standard operational environment, a single Tier-1 SOC analyst evaluates an average of **50 to 80 security alerts per shift**. Crucially, global cybersecurity literature reports that **70% to 90% of these alerts consist entirely of false-positives**.

This data deluge causes a critical cognitive friction phenomenon known as **Alert Fatigue**. When analysts are exposed to high volumes of non-actionable, low-severity security logs, their sensory thresholds adapt, leading to altered behavioral patterns:
* **Alert Suppression:** Arbitrary masking of low-to-medium alerts to reduce noise queues.
* **Visual Skimming:** Superficial inspection of log entries based purely on visual formatting rather than granular inspection.
* **Over-Reliance on Vendor Labels:** Uncritical trust in automated, out-of-the-box triage markers.

Consequently, subtle, low-signal **Indicators of Compromise (IoCs)** deployed by sophisticated threat actors are easily overlooked, enabling attackers to bypass defensive networks undetected. Traditional security dashboards compound this by displaying raw signatures and destination IP addresses with minimal environmental context. Analysts must manually correlate these logs across isolated database repositories—activities ripe for architectural automation.

## 🔬 2. Research Objective & Proposed Solution
This repository presents a functional, design-based engineering framework that constructs a **Retrieval-Augmented Generation (RAG) contextualization system** to streamline triage workflows and lower analyst cognitive load.

The system ingests raw incoming security logs and immediately passes them through an internal data-enrichment blender. By querying a localized Configuration Management Database (CMDB) profile layer at runtime, the application maps raw IP endpoints directly to their corporate department identities and business criticality metrics. 

This multi-layered dataset is fed directly into an in-context learning engine, completely avoiding the high computational overhead and system compiler locks associated with traditional model weight fine-tuning. The system then delivers a highly scannable, natural language incident report and an automated prioritization matrix directly onto a clean terminal display interface.
